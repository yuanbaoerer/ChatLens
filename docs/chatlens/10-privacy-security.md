# Privacy and security

Default local processing and scoped single group/date. User must have appropriate authorization to analyze/export and separately consent to external processing; membership alone does not establish others' consent. UI preview destination, data classes, volume and limits before cloud call; minimize/pseudonymize names, identifiers, contact details, credentials and sensitive text; redact images or keep local. Pseudonymization is not anonymization; warn about residual reidentification risk. No silent model upload, automatic forwarding, scraping beyond local authorized records, or client modification.

Local storage separate analytics workspace, least-privilege file access, safe path resolution, no credentials/raw messages in logs, telemetry, git, CI or release. Protect API keys with OS credential store or environment; no plaintext committed config. Ignore run artifacts, fixtures with real data, database/media/cache/export folders; verify existing ignores before editing. Provide clear deletion controls and retention settings. Export redacted by default; review before sharing. No automatic remote URL fetching. Treat message text/HTML/links as untrusted; escape report, validate paths/URLs, prevent prompt injection and arbitrary code/tool execution. Only typed provider requests with bounded payloads; fail closed when authorization absent.

Tests: no network when disabled, only selected group/time data, no raw IDs or secrets in payload/log, malicious text and HTML, traversal, partial/error and cancellation. Audit upstream updater before distribution: do not silently install upstream builds over fork or impersonate upstream; isolate release/config identity before packaging. Review third-party licenses and dependencies; GPL compliance does not resolve separate data access risks.
